# Добавление Google-аккаунтов через SSH-туннель

## Зачем это нужно

OAuth-клиент Antigravity принимает `redirect_uri` только на `localhost`. На продакшен-домене Google отклоняет запрос с ошибкой `redirect_uri_mismatch`.

SSH-туннель решает это: браузер и Google думают, что бэкенд на `localhost`, а трафик на самом деле идёт на сервер через зашифрованный канал.

После добавления аккаунта токены сохраняются в БД — туннель больше не нужен.

---

## Быстрый старт (2 шага)

### 1. Открыть туннель

```bash
ssh -L 8000:localhost:8001 -i ~/.ssh/servers deploy@<YOUR_SERVER_IP>
```

> [!NOTE]
> На Windows путь к ключу: `-i .ssh\servers` или `-i C:\Users\<user>\.ssh\servers`

**Не закрывай терминал** — пока он открыт, туннель работает.

### 2. Добавить аккаунт

Открой в браузере:

```
https://<your-domain.com>
```

1. Войди в админку
2. Перейди в **Credentials**
3. Нажми **Connect Google**
4. Выбери Google-аккаунт → подтверди
5. Готово — токен сохранён на сервере

Повтори для каждого аккаунта. Затем просто закрой терминал.

---

## Как это работает

```
Браузер (твой ПК)          SSH-туннель              Сервер (<YOUR_SERVER_IP>)
                          (AES-256)
                                                   ┌────────────────────┐
localhost:8000 ═══════════════════════════════════▶ │ 127.0.0.1:8001     │
   ▲                                               │      ▼             │
   │                                               │ Docker бэкенд:8000 │
   │                                               └────────────────────┘
   │
Google OAuth redirect_uri=http://localhost:8000/admin/auth/callback
```

1. Нажимаешь «Connect Google» на сайте
2. Бэкенд формирует OAuth-ссылку с `redirect_uri=http://localhost:8000/...`
3. Google показывает окно авторизации → подтверждаешь
4. Google редиректит браузер на `http://localhost:8000/admin/auth/callback?code=...`
5. SSH-туннель перехватывает запрос → отправляет на сервер
6. Бэкенд обменивает код на `refresh_token` и сохраняет в БД
7. Все дальнейшие API-запросы используют сохранённый токен — туннель не нужен

## Конфигурация сервера

Порт `8001` привязан к `127.0.0.1` в `docker-compose.yml` — он **не доступен из интернета**, только через SSH:

```yaml
backend:
  ports:
    - "127.0.0.1:8001:8000"   # только для SSH-туннеля
```

В `.env` на сервере:

```env
ANTIGRAVITY_OAUTH_CLIENT_ID=<см. .env.example>
ANTIGRAVITY_OAUTH_CLIENT_SECRET=<см. .env.example>
GOOGLE_REDIRECT_URI=http://localhost:8000/admin/auth/callback
ANTIGRAVITY_CLOUD_CODE_ENDPOINT=https://daily-cloudcode-pa.googleapis.com
```

> [!WARNING]
> `GOOGLE_REDIRECT_URI` должен быть `http://localhost:8000/admin/auth/callback`.
> С любым другим адресом Antigravity OAuth откажет.

## FAQ

**Безопасен ли туннель?**
Да. Порт `8000` открыт только на `127.0.0.1` твоего ПК. Трафик зашифрован (AES-256). Закрыл терминал — туннель исчез.

**Порт 8001 на сервере доступен извне?**
Нет. Он привязан к `127.0.0.1` — доступен только изнутри сервера (через SSH).

**Нужно ли что-то менять в docker-compose каждый раз?**
Нет. Конфигурация постоянная, ничего редактировать не нужно.

**Что если закрою терминал?**
Уже добавленные аккаунты продолжат работать. Для новых — снова открой туннель (шаг 1).

**Можно ли добавить несколько аккаунтов за раз?**
Да. Пока туннель открыт — добавляй сколько угодно.
